```sql

UPDATE hotels       ...（同规则）
UPDATE restaurants  ...（同规则）
UPDATE destinations ...（同规则）
```

- 黄果树：保留 `verified`（官方 `hgsly.cn`，confidence 0.92）
- 龙宫 / 天龙屯堡：改为 `pending` + 平台来源 URL（未取得稳定官方 URL，**不伪造** verified），票价/开放时间同规则降级为 pending

## 3. 阶段 2：重构规划请求与 AI 边界

### 3.1 解析器拆分（`crates/ai/`）

| 组件 | 位置 | 职责 |
|---|---|---|
| `RuleParser` | `crates/ai/src/rules.rs`（新） | 无外部依赖的确定性降级解析 |
| `LlmParser` | `crates/ai/src/lib.rs::llm_parse` | 可选 LLM 字段提取，失败回退规则解析 |
| `RequestValidator` | `crates/ai/src/request.rs`（新） | 统一字段/枚举/地域校验 |

- `parse_natural_text()` 返回 `Result<PlanRequest, String>`（旧入口 `parse_natural` 保留为 `#[deprecated]` 兼容别名）
- `validate_request()` 校验：origin/destination 非空、`end_date ≥ start_date`、days 与日期跨度一致、`people > 0`、`budget > 0`、transport/mode/intensity 枚举、interests/avoid 标签白名单、**V0.1 只接受贵州范围（`GUIZHOU_SCOPE`）**

### 3.2 LLM 权限边界

`merge_llm()` 新增事实字段黑名单：`ticket_price` / `opening_hours` / `open_time` / `close_time` / `weather` / `temperature` / `hotel_price` / `restaurant` / `itinerary` / `days_plan` 一律忽略并 `tracing::warn!`。

### 3.3 解析层修复的真实 bug

1. `input.find("从")` 按字节索引中文字符会 panic（`start byte index 1 is not a char boundary`）→ 改 `char_indices()`
2. `days` 匹配 `find_map` + `7天` 排在 `两天` 之前，「两天」被解析为 7 天 → 改为按序 `filter` + `next`
3. 「从贵阳出发去黄果树」被解析为目的地「贵阳」→ 目的地优先级改为 **景点关键词 > 市/州 > 出发地**，黄果树/龙宫/天龙屯堡统一映射「安顺」

## 4. 阶段 3：重写路线规划核心

### 4.1 移除硬编码目的地

删除：

```rust
if dest.contains("安顺") { cities = vec!["安顺","西秀","镇宁","黄果树"] }
else if dest.contains("贵阳") { ... }
```

改为 `resolve_destination_ids(pool, dest)`：目的地关键词 → `destinations` 表（name/full_path 模糊匹配）→ 召回关联景区；未命中则退回名称/城市模糊匹配。

### 4.2 SQL 与过滤增强

`recall_candidates` / `recall_by_cities` 均输出完整候选字段，并强制 `province='贵州'`、`status <> 'closed'`、`verification_status <> 'disputed'`。

### 4.3 错误类型与预算硬约束

```rust
pub enum PlanError {
    BudgetExceeded { limit: i32, total: i32 },   // → API 422 + code "BUDGET_EXCEEDED"
    NoCandidates(String),
    InvalidRequest(String),
}
```

- 门票按 `ticket_price × people` 累计（原来只计单人价，预算形同虚设）
- `fixed = tickets + lodging + food + transport + parking + other`；`slack = budget - fixed < 0` → 直接 `BUDGET_EXCEEDED`
- `reserve = min(10% × budget, slack)`；`total > budget` → `BUDGET_EXCEEDED`
- 住宿单价调整为 economy 100 / standard 180 / comfort 320（每夜每房），保证“预算 2000 + 3 核心景区”可出方案且不超支
- 删除旧的「降级 other + 打 warning」静默超支路径
- 算法版本 `rule-weighted-v1` → `rule-budget-v2`

### 4.4 时间轴与营业时间

- 新增 `fits_opening_hours(arrive, stay_min, open, close)`：`arrive ≥ open` 且 `arrive + stay ≤ close`，否则该日不排并产生 `opening_hours_conflict` warning
- 缺失开放时间的事实按 08:00–18:00 估算（同时打 `unverified_fact` warning）
- 每天仍检查：抵达时间太晚不排景区、午餐窗口、晚餐、酒店入住 21:30

### 4.5 输出保留 score / reason / candidate_source

`PlanItem` 新增 `score: Option<f64>` 与 `candidate_source: Option<String>`（景区节点填 `destination_recall`）。

## 5. 阶段 4：局部重规划

### 5.1 编辑操作（`crates/itinerary/src/lib.rs`）

```rust
pub enum EditOp {
    RemoveItem { item_id, day_index },
    ReplaceRestaurant { item_id, day_index, restaurant_id },
    MoveItemToDay { item_id, day_index, to_day_index },
    ReplaceHotel { item_id, day_index, hotel_id },
}
```

### 5.2 `apply_edit` 契约

返回 `ReplanResult { itinerary_id, changed_days, unchanged_days, diff, warnings, detail }`：

- `remove_item`：先按 `ref_id` 删 attraction + transit，无命中按标题兜底删（兼容旧数据）
- `replace_restaurant`：原位改 title/ref，cost 按 `price_per_person × people` 重算
- `move_item_to_day`：指定目标天，`to_day_index == day_index` 报 400
- `replace_hotel`：原位改酒店 title/ref
- 统一 `reorder_day`（按 `start_time NULLS LAST, sort_order` 重排 sort_order）+ `adjust_budget`（差额优先扣 tickets，其余扣 other，重算 total）
- 只写受影响天的 warnings，不动其它天数据

### 5.3 API 形状变化（破坏性，仅 V0.1 早期，暂无前端受影响）

```jsonc
// 旧
{ "itinerary_id": "uuid", "day_index": 1, "attraction_id": "uuid" }
// 新
{ "itinerary_id": "uuid", "edit_op": { "type": "remove_item", "item_id": "uuid", "day_index": 1 } }
```

`route::replan_remove_day_item` 修复：transit 在 attraction **之前**（前往景区），原实现只删后续 transit；现在前后皆删。

## 6. 阶段 5：认证与 API 基础设施

### 6.1 标准 JWT（`crates/auth/src/jwt.rs`，新文件）

- HS256 手写实现（SHA-256 + HMAC + base64url，纯 std，**无新增第三方依赖**）
- Claims：`{sub, role, iat, exp}`，7 天有效期；签名常量时间比较
- `JWT_SECRET` 为空 → 拒绝签发（Internal）
- **移除** `AppState.session: Arc<RwLock<HashMap<String, SessionUser>>>`
- 保留 `parse_token()`（旧透明 token `uuid.role.exp`）仅供过渡期

### 6.2 统一错误信封（`crates/common/src/error.rs`）

```json
{ "code": "VALIDATION_ERROR", "message": "...", "details": {} }
```

| HTTP | code |
|---|---|
| 400 | `VALIDATION_ERROR` |
| 401 | `UNAUTHORIZED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 422 | `UNPROCESSABLE_ENTITY`；预算硬约束为 `BUDGET_EXCEEDED` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |

`ApiError::from_plan_error_code(code, msg)` 把 `route::PlanError` 映射进来（用字符串码匹配，避免 `common → route` 循环依赖）。

### 6.3 cursor 分页（`crates/common/src/paging.rs`）

- 查询参数统一 `?limit=20&cursor=xxx`，响应 `{ "items": [], "next_cursor": "off:<n>|null", "meta": {...} }`
- cursor 对调用方不透明（V0.1 为偏移编码，可无缝换 keyset）
- 过渡期兼容 `?page=&page_size=`；非法 cursor 回落 offset 0
- 改造接口：`/destinations`、`/attractions`、`/hotels`、`/restaurants`（后两个从裸数组改为 `Paged<T>`）

### 6.4 幂等（阶段 5.4）

- `AppState.idempotency: Arc<RwLock<HashMap<String, (Instant, Value)>>>`，TTL 24h，2000 条容量保护
- `POST /travel/plan`、`POST /travel/replan` 读取 `Idempotency-Key`；命中直接返回缓存响应，不重复落行程
- Redis 路径已在 `AppState` 预留（当前进程内降级实现）

### 6.5 API 层重构（`apps/api/src/lib.rs` + `main.rs`）

- `main.rs` 只保留 `api::run()`；路由与 handler 迁到 `lib.rs`
- 新增 `build_router(config, state) -> Router` 与 `lazy_state(config) -> AppState`（`connect_lazy`，供集成测试复用）
- `current_user`：JWT 验签 → DB 拉用户 → `SessionUser`（无内存会话表）
- `travel/parse` 改为 `RuleParser → validate_request`：非法日期 400、非法预算/非贵州 422

## 10. 环境阻塞与已知限制

1. **PostGIS/pgvector 缺失**：本机 Homebrew PostgreSQL 17（5432）仅 `pg_trgm`，无 `youpji` 库。真实迁移、种子导入、e2e 无法执行。解法：起 `deploy/docker-compose.yml`（PG@5433），或 `brew install postgis pgvector` 后把 `DATABASE_URL` 指向 5432。
2. **JWT 为手写 HS256**：开发期无外部依赖的权宜实现，已有已知向量测试与常量时间比较；上生产建议换 `jsonwebtoken` 并支持密钥轮转。
3. **幂等为进程内实现**：Redis 路径已在 `AppState` 预留，多实例部署需改 Redis 键。
4. **`travel/replan` 请求体变更**：无前端受影响，但调用方需迁移到 `edit_op`。
5. **工作区不是 git 仓库**：无 `.git`，无法回滚；建议尽快 `git init` 并首提。
6. **一次文件事故**：并行 `mv` + `cat` 覆盖了 `apps/api/src/main.rs`，已按已有读到的 handler 全量重写为 `lib.rs`，`cargo check` 逐路由核实一致。
