## 第 1 轮：基线与核心缺陷修复（`782fbb5`）

这是仓库的基线提交：git 初始化 + 一批工程基建修正 + 三类核心缺陷修复。
规模 67 files / 15104 insertions。

### 工程基建

- CI 的 `working-directory` 原本指向不存在的 `backend/`，实际代码在 `youpji/backend`，修正之。
- CI 增加迁移 + 种子校验与镜像构建；本地 Postgres 缺 PostGIS 时由 CI 兜底。

- docker compose 合并为单文件，服务名对齐 `DESIGN.md §12`；`web` / `admin` 放入 profile，
  避免未构建前端产物时启动失败。
- README 的目录树与启动命令同步更新。

### 安全与正确性

| 问题 | 修复 |
|---|---|
| `GET /itineraries/:id` 无鉴权，可读他人行程 | 补 JWT 校验 + 归属校验，非本人且非 admin 返回 `403 FORBIDDEN` |

这三条落到 `AGENTS.md` 的隐私约定：**行程默认私有，日志与埋点不得输出精确轨迹明文**。

### 重规划（局部重规划，铁律 8）

- `apply_edit` 纳入**单事务**，消除「节点已删、顺序未重排」的半成品状态。

- 删除节点 / 跨天搬运后重算时间轴与车程，不再留下时间空洞。

## 第 2 轮：景区数据采集校验流水线（`a420dd8`）

主题：把 `AGENTS.md` 铁律 4「AI 不决定事实」从口号变成**可执行断言**。

### 三个脚本

| 脚本 | 职责 |
|---|---|
| `scripts/import-attractions.mjs` | 事实校验：`verified` 必有 `source_url` 且 `confidence ≥ 0.7`、经纬度写反/出省检测、评分越界检测、名称查重 |
| `scripts/geocode.mjs` | 高德 POI 搜索按名取点，带缓存与限速 |
| `scripts/build-attraction-seed.mjs` | 流水线：合并 → 补坐标 → 坐标系归一化 → 事实校验 → 坐标关卡 → 生成 SQL |

### 坐标系归一化（关键修正）

六盘水批次坐标来自 OSM / Nominatim（WGS-84），与高德 POI（GCJ-02）混存会导致：

- PostGIS 就近查询偏 412–480 m
- 高德驾车矩阵收到错坐标

流水线内置 WGS84 → GCJ-02 折算，原值与偏移量写入 `coord_note` 留痕。实测 8 条折算偏移
412–480 m，落在境内典型区间。

### 数据入库

- 六盘水 8 条带坐标景区入 `seed.sql`（妥乐古银杏、明湖湿地公园为 `verified`，票价来自官网/政府页）。
- 安顺 / 铜仁黔西南两批 15 条事实数据已核验但无坐标，按坐标关卡**不入库**，带完整
  `source_url` 存档于 `youpji/data/attractions/` 待补坐标。
- 贵州 9 个市州行政区划补全（落 `pending`，交 Admin 审核）。

### 核验中拦下的数据污染

这一轮的真正价值在于记录**哪些数据不可信**：

- 万峰林官网「周边景点」页的开放时间是万峰林自身侧栏组件，不适用于马岭河峡谷/万峰湖 → 未采纳
- 北盘江大桥、水城古镇的 `source_url` 实指向其他景区 → 置空，避免误导
- 「双龙古镇」经检索在六盘水不存在、「凉都」是六盘水别称 → 剔除
- 梵净山票价官网仅有图片、二手口径互相冲突（100/288/290/308）→ 留 `null` 不猜

测试：fmt/clippy 通过，79 测试 0 失败。

## 第 3 轮：OSM 回退坐标源（`a9fc955`）

主题：**坐标不再依赖高德 Key**。

### 成果

- `geocode` 增加 OpenStreetMap Nominatim 回退（WGS-84），无 Key 也能补坐标。
- 补全结果持久化回各批次源文件，坐标成为**可审计数据**而非临时结果。
- 23 条缺坐标补上 17 条，种子从 8 → 32 条（5A 6 / 4A 14 / 3A 1）。

### 同名地物污染防护

Nominatim 会把同名地物当成景区，实测拦下的错误匹配：

| 查询词 | 错误匹配 |
|---|---|
| 黄果树 | 沪昆高速黄果树服务区 |
| 龙宫 | 河南濮阳「龙宫」、北京化工大学 |
| 野玉海 | 澳门「御海 Sea Imax」 |
| 龙里龙架山森林公园 | 兰州、合肥同名森林公园 |

解析器加**三重过滤**：行政区归属、类目、地物类型。

### 坐标系安全

- 坐标系无法判定的记录**一律不入库**（此前会按 WGS-84 盲目折算，造成二次偏移）。
- 新增 `coord_note` 文本推断坐标系，兼容只写备注不写 `coord_sys` 的记录。
- 共 25 条 WGS-84 折算为 GCJ-02，偏移 412–480 m 全部留痕。

新增 `data/attractions/README.md` 记录流水线、关卡与污染源。

## 第 4 轮：接入省政府景点名录（`7bea243`）

主题：**票价瓶颈取得一级权威来源**。

### 来源突破

贵州省人民政府「景点名录」提供 532 家 A 级景区，含「是否收门票」与「门票价格（元）」，
属**一级政府来源**。

> 此前逐个核验 38 条仅得 `verified` 4 条，票价长期是瓶颈；名录解决了它。

来源：<https://www.guizhou.gov.cn/ztzl/wzgz/yzgz/jdml/>

### 实现

- `scripts/import-gov-registry.mjs` 解析名录，票价取字段首个数字（成人/门票/旺季主档），
  原文全文写入 `note` 供人工复核口径。
- 合并策略：名录做**价格权威**，逐个核验批次补坐标/时间/分类评分，按核心地名匹配；
  核验批次拿到官方双来源时覆盖名录的 `pending`。
- 合并后 566 条，21 条被核验数据补强，34 条名录未收录的核验记录保留。

### 批量补坐标的工程修正

- `geocode` 支持 `--limit`，流水线 `GEOCODE_LIMIT` 贯通（此前参数未传入导致全量查询）。
- 缓存改为逐条增量落盘：批量任务被中断不再丢失已完成部分。
- 429 限流识别与 10 分钟冷却，避免把限流当成「查无此地」写入缓存。
- 修正 geocode 报告口径：缺坐标数应为真实缺口而非本轮查询数。

### 产出

可入库 32 → 48 条（verified 6 / pending 36 / unverified 6），覆盖全部 9 个市州。
当时判定铁律缺口 52 条，**全部卡在坐标而非票价**。

## 第 5 轮（未提交）：重规划能力 / 数据完整性 / UI 原型

工作区同时推进三条线，尚未提交。

### 5A. `reorder_day`——用户指定当天顺序

**设计落点**：`DESIGN.md §8.3` 新增 `reorder_day` 段落。

关键决策（已写入 DESIGN）：

- `edit_op` 增加 `reorder_day`。
- 只支持「**锁定前缀**」，不支持完整置换顺序：用户可把想去的项提到前面，但不能让低分景区
  整体压过高分项，否则 `Route Score` 失效、行程质量失控。
- 实现复用 `route::pack_day` 纯函数——把候选遍历序由「评分降序」换成「用户序在前」，
  时间轴、营业时间校验、预算累计**全部重新推导**，不做字段级覆盖。
- 重排只作用于 `day_index` 指定的那一天，`unchanged_days` 必须包含其余所有天（铁律 8 的直接落点）。
- 餐厅/酒店/交通段节点不接受拖拽。

> 核心原则：**用户能定序，但不能定出违规行程。**

代码改动：

| 文件 | 内容 |
|---|---|
| `crates/route/src/lib.rs` | 新增 `validate_reordered_day` 与 `DropReason`。交通段按 `duration_min` **重算**结束时间并推进 cursor（否则后续节点沿用重排前时刻 = 时间轴没重算）；`reorder_too_late`（≥18:00）与 `opening_hours_conflict` 两类剔除原因 |
| `crates/itinerary/src/lib.rs` | 新增 `EditOp::ReorderDay { day_index, ordered_attraction_ids }` 与 `apply_reorder_day`：提前缀 → reflow → 硬约束复核剔除 → 删除孤儿 transit → **二次 reflow** → 写回 `sort_order`（先整体取负避 UNIQUE 冲突） |
| `crates/route/src/route_tests.rs` | 新增 6 个测试：时间轴按新序重算 / 营业时间冲突剔除 / 超 18:00 剔除 / 忽略 transit 与 free / 无营业时间不误杀 / 空行程 |

### 5B. 营业时段抽取入库（数据阶段 2.5）

**为什么单独解析高德营业时间，而不是直接写 `attractions.opening_time`：**

1. 高德返回的是**自由文本**，形如「9月1日至11月30日 07:00-18:30开放(16:00停止售票…)；
   12月1日至次年2月28日 07:30-18:00开放…」。同一景区有淡旺季差异（梵净山还有春节与
   东西线差异），`attractions` 表的单一 `opening_time` / `closing_time` 根本表达不了。
2. 高德是**二级来源**，按铁律 4 与 `0002` 的 `fact_status_check`，必须落 `pending` +
   `confidence < 0.7`，不允许标 `verified`。
3. 只**追加**候选行，不覆盖核验批次里已有的官方开放时间。

解析器新增 `parseWeekdays` / `parseSeason` / `parseClock`；覆盖全周的「周一至周日」折叠成
`null`（schema 约定 null = 每天），否则会摊成 7 行完全相同的记录；跨年区间「12月1日至
次年2月28日」的「次年」用专门分支处理。

两个新迁移（遵循「只追加不改历史」）：

- **`0003_attraction_hours_facts.sql`**
  - `attraction_hours` 补 `source_time` 与 `confidence`——0001 只给了 `source_type` /
    `last_verified` / `verification_status`，0002 补了 `source_url`，仍缺这两个，导致
    `fact_status_check()` 无法作用于营业时段（二级来源的高德营业时间会被无约束写成
    `verified`）。补齐后数据库层才有兜底。
  - 唯一索引 `uq_attraction_hours_slot`（含 `open_time`/`close_time`）：只去掉**完全重复**的行；
    若只按 `(attraction_id, weekday, season)` 去重，会把同一季节下的不同开放区间误判为重复而丢弃。
  - 巡检索引 `idx_attraction_hours_review`，支撑「候选时段 vs 官方时段」的比对查询。

- **`0004_attractions_name_unique.sql`**
  - 背景：`attractions` **没有 name 唯一约束**，导致两处静默故障——
    `attractions.generated.sql` 里的 `ON CONFLICT DO NOTHING` 完全是空转，种子重复 apply
    会无限追加重复景区；而 `hoursToSql` 用 `(SELECT id FROM attractions WHERE name=…)` 定位
    归属，一旦重名，时段就会挂到多行上，表现为「昨天能导入，今天重跑突然失败」。
  - 先自愈：每组重名保留「验证状态更好、同状态保留更新更晚」的一条，其余删除。删除会级联
    `attraction_hours` / `attraction_tickets` / `attraction_tags`（均为 `ON DELETE CASCADE`）——
    这是有意的，重名行本来就没法被唯一引用。
  - name 之所以能单独作唯一键：种子合并阶段已按 `coreName`（去掉「景区/旅游区/风景区」等
    后缀后的核心地名）全局去重，当前 566 条名录重名数为 0；且 V0.1 只做贵州一省。
  - 补 `idx_attractions_alias_trgm`（0001 只建了 name 的 trgm 索引，而「黄果树 →
    黄果树风景名胜区」正是别名检索入口）。

顺带修掉一个会让整个种子导入失败的 bug：`best_season` 是 `TEXT[]`，而普通 `sqlLiteral` 会
输出 `'四季'`，PostgreSQL 报 `malformed array literal`。新增 `sqlArrayLiteral` 处理。

`hoursToSql` 的三条纪律：高德一律 `source_type='map'` / `verification_status='pending'`；
`confidence` 固定 `0.55`（低于 0.7 阈值，数据库侧也无法被误升为 `verified`）；归属靠
`(SELECT id FROM attractions WHERE name=…)`。其中用
`SELECT ... FROM (VALUES ...) WHERE attraction_id IS NOT NULL` 而非 `INSERT ... VALUES`
——子查询查不到景区时返回 NULL，而 `attraction_id` 是 NOT NULL 外键，直接 INSERT 会让
**整条语句**中止，连带已能匹配的行一起回滚。

产出：**460 条营业时段候选行**（`pending`，待人工核验）。

### 5C. UI 原型

两份 HTML 均在 `Docs/`，未接入 Flutter 工程，属设计评审用静态件：

- **`ui-layout-plan.html`**——布局规划。信息架构、主线三屏线框、贯穿全 App 的四条硬规则、
  页面 → 路由 → 接口映射、栅格与适配。配色为米白 + 松绿（`--cream` / `--primary:#2f6f5e`）。
- **`ui-prototype-v2.html`**——可交互原型，主题 **Ocean Mist 雾海蓝**
  （`#06425C / #4A90A4 / #A8D5BA / #F4F1DE`），深浅色双模式。覆盖 12 屏：
  首页 / AI 规划 / 生成中 / 行程详情 / 探索 / 景区详情 / 攻略 / 攻略详情 / 我的 / 收藏 /
  行程列表 / 筛选。

原型中把数据治理的约束直接做成了可见的 UI 表达，与铁律呼应：每条事实都带
「来源类型 · 上次核验时间」（景区官方票务一级 / 地图地点二级 / 社区图文三级 / 来源估算），
预算条明确提示「预算装不下时系统会先降级重排，仍超限才报错」。
