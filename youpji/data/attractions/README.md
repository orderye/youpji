## 流水线

```bash
npm run attractions:check    # 试跑，只出报告
npm run attractions:build    # 校验并生成 seed SQL
AMAP_KEY=xxx npm run attractions:build   # 高德优先取点
```

阶段：合并去重 → 坐标补全 → 坐标系归一化 → 事实校验 → 坐标关卡 → 生成 SQL。

## 三道强制关卡

1. **事实校验** — `verified` 必须有 `source_url` 且 `confidence ≥ 0.7`；
   票价/开放时间缺失一律落 `pending`/`unverified`，不允许用估算值冒充。
2. **坐标系归一化** — OSM/Nominatim 返回 WGS-84，高德返回 GCJ-02。
   境内相差 300–600 米，混存会让 PostGIS 就近查询与驾车矩阵整体偏移。
   流水线自动折算，原值与偏移量写入 `coord_note` 留痕。
   **坐标系无法判定的记录不入库。**
3. **坐标完整性** — 无坐标不入库。坐标是路线引擎召回与距离计算的硬依赖，
   没有坐标的景区进了库也进不了候选池。

## 坐标来源优先级

1. 高德 POI 搜索（`AMAP_KEY`）— GCJ-02，与存储口径一致，精度最高
2. OpenStreetMap Nominatim — WGS-84，需折算

Nominatim 会把同名地物当成景区，解析器已加三重过滤：
行政区归属、类目、地物类型。实测拦下的错误匹配：

- 「黄果树」→ 沪昆高速黄果树服务区（非瀑布景区）
- 「龙宫」→ 河南省濮阳市「龙宫」、北京化工大学
- 「野玉海」→ 澳门「御海 Sea Imax」
- 「龙里龙架山森林公园」→ 兰州市、合肥市同名森林公园

## 采集时的已知污染源

- **携程/本地宝的「附近景点」模块**会把邻近景区票价混入正文。
  核验时必须用「名称邻近 + 省份邻近」双重校验逐条比对。
- **景区官网常把价目表做成图片**，文本层取不到票价；
  此时留 `null`，不要采信二手来源互相冲突的数字（如梵净山 100/288/290/308）。
- **「开放时间」侧栏组件**可能属于母景区而非当前条目
  （万峰林官网的周边景点页即如此）。
